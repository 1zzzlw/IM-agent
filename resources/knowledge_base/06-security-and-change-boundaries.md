# 安全与变更边界

## 用户身份

生产环境应以网关鉴权后透传的可信身份为准，不能无条件相信请求体中的 `user_id`。所有会话、消息、工作区、索引和工具结果都必须验证用户归属。

## 密钥

API Key、数据库密码、Redis 密码、令牌和私钥不得写入日志、向量数据库、知识库、模型提示词或接口响应。读取项目文件时应默认过滤 `.env`、私钥和凭据文件。

## 模型输出

模型输出不是可信命令。工具名称必须来自允许列表，参数必须经过结构化校验。模型不能自行扩大工作区、跳过用户确认或声称已完成未验证的操作。

## 写入边界

只修改用户要求范围内的文件。发现无关问题可以报告，但不要顺手删除或重构用户已有代码。覆盖、删除、批量移动和执行系统命令需要更严格的目标检查。

## 多用户隔离

向量检索、Redis 键和数据库查询都需要用户维度。推荐键结构：

```text
user_id + workspace_id + resource_id
```

只用工作区名称、会话标题或文件名都不足以保证隔离。

## 知识库边界

知识库内容只提供工程经验和检索上下文。不可遗漏的安全策略必须进入固定系统提示、请求校验和工具执行器。RAG 可能检索不到某篇文档，因此不能承担强制授权职责。
