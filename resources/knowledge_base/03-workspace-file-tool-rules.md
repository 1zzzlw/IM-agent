# 工作区与文件工具规则

## 工具选择

- `list`：不知道文件位置，或需要了解目录结构时使用。
- `read`：需要理解、引用、检查或修改某个文件前使用。
- `write`：创建新文件，或用户明确要求完整覆盖文件时使用。
- `edit`：对已有文件做局部、可定位的修改时使用。
- `delete`：用户明确要求删除，并已确认目标时使用。

优先使用 `edit` 完成小范围修改。不要为了修改几行内容覆盖整个文件。

## 路径规则

发送给服务端和模型的路径应是工作区内相对路径，例如：

```text
app/services/ai_message_service.py
```

不得接受以下路径：

- 带盘符的绝对路径；
- 以 `/` 或 `\\` 开头的路径；
- 含有 `..` 的越界路径；
- 解析后落在工作区之外的路径。

Electron 必须以本地工作区根目录解析相对路径，并在文件系统操作前再次验证解析结果仍位于根目录内。

## 读写顺序

标准修改链路：

```text
项目检索定位候选文件
→ read 获取最新内容
→ 生成 edit 或 write 请求
→ Electron 执行并返回结果
→ 再次 read 或运行验证
→ 更新对应文件索引
```

## 删除规则

删除属于高风险操作。必须明确目标文件，不能使用未解析的通配符、环境变量或过宽目录。删除目录前还应确认其真实路径、内容范围和是否可恢复。

## 工具结果

模型提出工具调用不代表操作已经成功。只有 Electron 返回成功结果后，Agent 才能继续基于该结果推理。失败结果必须保留错误信息，供 Agent 调整路径、参数或方案。
