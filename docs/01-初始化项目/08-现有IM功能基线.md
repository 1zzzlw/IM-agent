# 现有 IM 功能基线

## 1. 说明

本页主要根据 Electron/Vue 前端源码与少量网关、旧 AI 接口源码整理，用来确定 imAgent 要接入的已有系统环境。

“前端已有”只表示页面、状态管理或调用入口存在，不等于对应 Java 接口、数据库和生产部署已经完成联调。

## 2. 客户端技术结构

现有客户端是 Electron 桌面应用，分为三个运行边界：

| 边界 | 主要职责 |
|---|---|
| Electron 主进程 | 窗口、托盘、WebSocket、本地 SQLite、文件分片、FFmpeg、系统能力 |
| Preload | 通过 `contextBridge` 向页面暴露有限 IPC API |
| Vue 渲染进程 | 页面、路由、Pinia 状态、HTTP 接口和用户交互 |

渲染进程不应直接获得 Node.js 的任意权限。未来 Vibe Coding 如果在本机执行文件或命令操作，也应沿用“渲染层发起 → preload 暴露有限能力 → 主进程校验执行”的安全结构。

## 3. 已有业务模块

### 3.1 账号与客户端状态

- 登录、注册、手机验证码和头像上传页面；
- 上次登录账号确认；
- access token 保存与刷新；
- 路由鉴权；
- 用户资料、账号、通知、快捷键和存储路径设置。

Agent 接入原则：复用现有登录态和网关鉴权，不新增独立 AI 账号。

### 3.2 好友与群组

- 好友搜索、申请、同意、删除、备注和黑名单状态；
- 好友上线/离线状态；
- 创建群聊、群申请、群成员列表；
- 群名称、成员邀请、踢人、管理员、禁言、转让群主、退出与解散。

Agent 接入原则：第一阶段不读取完整好友或群组数据；后续若提供“总结群聊”等能力，必须通过受控内部接口和用户授权获取。

### 3.3 会话与消息

- 单聊、群聊和 AI 会话；
- 会话置顶、免打扰、未读数、删除和独立窗口；
- 文本、图片、视频、音频、文件、红包和系统消息组件；
- 引用、撤回、发送状态、ACK 与超时处理；
- WebSocket 心跳、断线重连和消息广播；
- 本地 SQLite 保存消息、会话、好友关系和收藏。

当前约定中：

- `conversation.type = 0`：单聊；
- `conversation.type = 1`：群聊；
- `conversation.type = 2`：AI 会话。

Agent 接入原则：AI 文本生成走 HTTP + SSE，普通聊天实时消息继续走现有 WebSocket 协议。

### 3.4 文件与媒体

- 文件分片 hash、并发上传、暂停/恢复和下载；
- 图片与视频预览；
- FFmpeg/FFprobe 媒体处理；
- MinIO 作为现有对象存储能力。

Agent 接入原则：头像和未来多模态附件优先复用现有文件服务，不在 Python 服务内再造一套通用上传系统。

### 3.5 内容与社交

- 收藏列表；
- 富文本笔记创建和编辑；
- 朋友圈发布、详情、评论、回复、点赞和图片懒加载。

这些属于现有 IM 内容域，不纳入 imAgent 第一阶段。未来可以通过只读工具提供“总结笔记”“生成朋友圈文案”等能力。

### 3.6 钱包与红包

- 已有钱包页面和红包组件；
- 部分充值、提现展示或交互已经存在；
- 转账、收款以及红包完整状态仍有待后端闭环。

Agent 不应直接发起支付、转账或红包操作。未来即使增加相关工具，也必须属于高风险操作并经过明确确认。

## 4. 当前 AI 前端能力

| 能力 | 前端现状 | imAgent 需要补齐 |
|---|---|---|
| AI 会话入口 | 会话类型 2 跳转 `/aiChat` | 会话创建、归属与持久化 |
| 文本发送 | 调用 `/ai-message/sendMessage` | 真实模型调用与 SSE |
| 流式展示 | 可追加文本片段 | 健壮事件解析、错误和终态 |
| 历史消息 | 调用 `/ai-message/loadMessage` | 按会话分页接口 |
| 角色列表 | 已有抽屉与 Store | 查询与权限控制 |
| 创建角色 | 已有表单与头像 | multipart 接口和文件存储 |
| 更新/切换/删除 | 已有调用入口 | 事务、归属和默认角色规则 |
| 新对话 | 有文字入口但未见完整处理 | 新建会话和上下文隔离 |
| 图片 | 有文件选择入口 | 第二阶段多模态协议 |
| Agent 工具状态 | 尚无通用组件 | SSE 工具事件和审批 UI |

## 5. 网络入口

### HTTP

开发环境中，渲染进程请求 `/api`，由前端开发服务器代理到统一 HTTP 入口 `127.0.0.1:81`。生产配置使用统一服务地址。网关再按路径将请求分发到各微服务。

AI 路由已配置为：

```text
/ai-message/** -> lb://im-agent
```

### WebSocket

Electron 主进程连接现有 WebSocket 入口，使用自定义二进制协议承载普通 IM 消息、好友/群组事件和 ACK。AI 的 SSE 不应复用这套消息类型，除非未来明确需要“后台 Agent 完成后主动通知”。

## 6. imAgent 可复用的现有能力

- 网关统一入口与 JWT 鉴权；
- Nacos 服务发现；
- 用户与登录态；
- MySQL、Redis、RabbitMQ 和 MinIO 等部署基础；
- Electron 的文件选择、窗口与本地能力；
- 会话列表和 AI 会话 UI；
- 统一暗色界面与消息展示组件。

复用不等于直接访问所有数据库表。跨领域数据优先通过稳定接口获取，避免 imAgent 与 Java 内部表结构强耦合。

## 7. 最自然的 Agent 产品入口

结合现有前端，第一阶段可以保留三个入口层级：

1. AI 会话：普通问答、角色对话；
2. Agent 模式：在同一会话中显示计划、工具状态和审批卡片；
3. 编码工作区：从 AI 会话进入一个明确绑定本地目录的 Vibe Coding 任务。

这样可以复用现有会话体验，同时保持普通聊天、Agent 运行和编码任务的数据边界。
