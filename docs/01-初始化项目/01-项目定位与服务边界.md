# 项目定位与服务边界

## 1. 项目定位

`imAgent` 是 IM 系统的 AI 能力服务，使用 Python 实现，并通过 Nacos 注册到现有微服务体系。它通过网关对客户端提供统一接口，但不直接承担普通即时通讯功能。

推荐的一句话定义：

> imAgent 为现有 IM 客户端提供流式 AI 对话、可控工具调用、编码任务编排以及后续的多模态与记忆能力。

## 2. 为什么单独拆分 Python 服务

- Python 的 LangChain、LangGraph、模型 SDK 和 AI 工具生态更完整。
- Agent 工作流、模型供应商和提示词可以独立迭代，不影响 IM 核心链路。
- AI 请求通常耗时较长，适合与普通 HTTP 业务、Netty 实时消息链路分开扩缩容。
- Java 服务继续保障账号、关系链、普通聊天等稳定业务，Python 服务聚焦 AI 领域。

## 3. 服务职责划分

| 领域 | 推荐负责人 | 说明 |
|---|---|---|
| 登录、注册、令牌刷新 | Java 认证服务 | imAgent 不签发登录令牌 |
| 网关鉴权与路由 | Java 网关 | 校验令牌并透传可信用户信息 |
| 好友、群组、普通会话 | Java IM 服务 | 保持现有实现 |
| 普通消息、离线消息、ACK | Java/Netty 服务 | 不迁移到 imAgent |
| 文件通用上传与对象存储 | 现有 Java/文件服务 | Agent 可通过受控客户端调用 |
| AI 会话、AI 消息 | imAgent | 新服务的核心业务数据 |
| 个性化角色 | imAgent | 与 AI 对话强相关，应由同一领域维护 |
| 模型调用与流式输出 | imAgent | 统一屏蔽模型供应商差异 |
| Agent 编排与工具调用 | imAgent | LangGraph 等编排逻辑放在此处 |
| Vibe Coding 任务 | imAgent | 任务编排在服务端，文件操作需安全边界 |
| 视频通话信令与媒体流 | 待设计 | 不属于第一阶段 |
| 长期记忆 | imAgent | 第三阶段建设，短期不提前复杂化 |

## 4. 数据归属原则

### 4.1 用户身份

用户身份以网关鉴权结果为准。客户端提交的 `user_id` 只能作为兼容字段，不能作为可信身份来源。

推荐链路：

1. 客户端携带 `Authorization`；
2. 网关验证 JWT 与 Redis 登录态；
3. 网关写入 `user-info`；
4. imAgent 解析并校验 `user-info`；
5. 业务代码只使用解析后的当前用户 ID。

imAgent 的 9090 端口应只允许网关或受信网络访问，否则调用方可伪造 `user-info`。

### 4.2 AI 业务数据

推荐由 imAgent 独占以下数据的写入权：

- AI 会话；
- AI 消息；
- 个性化角色；
- Agent 运行记录；
- 工具调用与审批记录；
- 记忆条目及其索引元数据。

可以与现有系统共用一个 MySQL 实例，但建议使用独立表前缀或独立 schema，并且避免 Java、Python 双方同时写同一张表。

### 4.3 旧 AI 数据迁移

现有 Java `im-chat` 中已有 `ai_message` 与 `ai_personality` 相关实现，而网关现在已经把 `/ai-message/**` 指向 `im-agent`。因此必须选择单一迁移方案：

- 推荐：将 AI 数据写入权迁移给 imAgent，旧数据做一次性迁移，Java 端旧接口停止提供服务；
- 临时方案：imAgent 通过明确的内部接口读取旧数据；
- 不推荐：Java 与 Python 同时直接写同一批 AI 表，容易出现字段、事务和版本不一致。

## 5. 第一阶段范围

### 5.1 必须完成

- 统一配置、日志、异常响应和请求标识；
- Nacos 注册、注销和基础健康检查；
- 从网关用户头恢复当前用户；
- AI 会话创建、列表与历史消息；
- 文本消息的 SSE 流式回复与完整消息落库；
- 个性化角色的创建、列表、更新、切换和删除；
- 最小 Agent 工具调用链；
- 最小 Vibe Coding 安全闭环；
- 单元测试、接口契约测试和一条真实联调链路。

### 5.2 暂不纳入

- 视频通话；
- 图像识别；
- 实时三维建模；
- 跨会话长期记忆；
- 多 Agent 自主协作；
- 无人值守的任意终端执行；
- 大规模向量知识库和复杂 RAG 平台。

## 6. 边界规则

1. imAgent 不绕过网关自行实现另一套登录系统。
2. imAgent 不复制好友、群聊和普通消息表。
3. HTTP 接口与 SSE 事件必须有版本化、可验证的数据契约。
4. 模型输出不是可信指令；所有工具参数都要经过程序校验。
5. 读取操作与写入操作分级，写文件、执行命令等高风险动作必须受工作区和审批约束。
6. 对话历史、任务运行记录、长期记忆是三类不同数据，不混为一张“消息表”。
