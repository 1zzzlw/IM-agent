# 第一阶段实施路线

## 1. 实施原则

- 每个里程碑都形成一个可演示闭环；
- 先稳定普通 AI 对话，再引入工具；
- 先实现单 Agent，再考虑复杂编排；
- 先实现只读编码工具，再允许修改和命令执行；
- 每一步同时补测试和可观测性，不把它们全部留到最后。

## 2. 里程碑总览

| 里程碑 | 目标 | 完成标志 |
|---|---|---|
| M0 基线固化 | 明确契约并修正服务骨架 | 启停、注册、健康检查可验证 |
| M1 流式聊天 | 打通端到端文本对话 | 前端经网关稳定接收完整 SSE |
| M2 会话持久化 | 支持多个会话和历史 | 会话隔离、分页、重进可恢复 |
| M3 个性化角色 | 补齐现有前端功能 | CRUD、切换、权限测试通过 |
| M4 Agent 基础 | 完成一次可观察工具调用 | 状态、事件、失败与取消闭环 |
| M5 Vibe Coding MVP | 完成受控代码修改 | 读、改、diff、测试、审批闭环 |
| M6 联调与发布 | 可重复部署与回归 | 全链路验收、文档与回滚方案齐全 |

## 3. M0：基线固化

### 任务

- 确定请求与响应字段规范；
- 为旧 camelCase 请求提供短期兼容策略；
- 将当前用户解析封装为 FastAPI 依赖；
- 添加统一错误模型和 `request_id`；
- 增加 `/health/live` 与 `/health/ready`；
- 修正并测试 Nacos 注册、注销与优雅停机；
- 将直接依赖补充到 `pyproject.toml`；
- 建立 pytest 基础结构与应用测试客户端。

### 验收

- 缺少合法 `user-info` 时业务接口返回 401；
- 进程启动后能在 Nacos 查到 `im-agent`，正常退出后实例消失；
- 存活检查不依赖模型，模型不可用时就绪检查能反映原因；
- 配置测试不读取或输出真实密钥；
- 单元测试可在不访问真实模型和 Nacos 的情况下运行。

## 4. M1：流式聊天

### 任务

- 复用模型客户端，不在每次业务调用中散落初始化逻辑；
- 将 `sendMessage` 改为异步流式接口；
- 定义并输出结构化 SSE 事件；
- 设置模型超时、最大输出和并发限制；
- 前端使用完整 SSE parser，并按消息 ID 更新；
- 补齐 loading、取消、失败和重试交互；
- 临时使用内存仓储或测试数据库完成闭环。

### 验收

- 中文、换行、空格、Markdown、代码块在分片后不丢失；
- 首个事件包含 `run_id` 和 `message_id`；
- 流结束时只有一个终态；
- 客户端中断后服务端停止无意义生成或及时标记状态；
- 模型异常不返回内部堆栈和密钥信息。

## 5. M2：会话与消息持久化

### 任务

- 建立 AI 会话、消息、运行记录表；
- 用数据库迁移管理表结构；
- 实现新建、列表、改名、归档会话；
- 历史消息按 `conversation_id` 游标分页；
- 保存用户消息、助手完整消息与运行终态；
- 通过 `client_message_id` 处理重复提交；
- 确定旧 Java AI 数据的一次性迁移或放弃策略。

### 验收

- 用户无法查询或修改其他用户的会话；
- 两个会话的上下文完全隔离；
- 重启服务后历史仍可恢复；
- 流式生成失败时运行状态可查询，数据库不存在“假完成”；
- 历史分页无重复、无跳页，并保持稳定顺序。

## 6. M3：个性化角色

### 任务

- 对齐前端已有五个角色接口；
- 实现角色归属与系统预设规则；
- 复用现有文件服务或 MinIO 能力保存头像；
- 通过事务保证每个用户最多一个激活角色；
- 将角色快照或 ID记录到消息/运行中；
- 修复前端空头像、删除当前角色和请求失败处理。

### 验收

- CRUD 和切换功能经网关联调通过；
- 越权修改返回 404 或 403；
- 并发切换后仍只有一个激活角色；
- 删除激活角色后对话可以继续使用默认助手。

## 7. M4：Agent 基础

### 任务

- 定义 Agent State 与运行状态机；
- 建立模型节点、工具节点和结束路由；
- 首批只提供 1 至 2 个低风险工具；
- 增加最大步骤数、总超时和取消信号；
- 将工具事件加入 SSE；
- 保存工具调用摘要与结果状态；
- 对模型生成的工具参数做 Pydantic 校验。

### 验收

- 普通问题可以直接回答，不强制调用工具；
- 需要工具的问题只调用白名单工具；
- 参数非法、工具超时、模型循环都能进入明确失败状态；
- 前端能区分“正在思考、正在调用工具、已完成、失败”；
- 相同输入可通过模型替身完成稳定自动化测试。

## 8. M5：Vibe Coding MVP

### 任务

- 定义工作区会话与路径安全策略；
- 实现列目录、读文件、搜索文本三个只读工具；
- 实现补丁提议和 diff 预览；
- 增加用户审批后应用补丁；
- 仅开放 lint、test、build 等允许命令；
- 限制命令时间、输出量和并发；
- 记录每次文件变化与验证结果。

### 验收场景

准备一个临时 Git 仓库，要求 Agent 修复一个带失败测试的小问题：

1. Agent 只能看到选定工作区；
2. 未批准前文件不发生变化；
3. 批准后只修改计划内文件；
4. 测试由允许命令执行并回传结果；
5. 最终答复列出改动和验证证据；
6. 尝试读取工作区外文件、`.env` 或执行危险命令时被拒绝。

## 9. M6：联调与发布

### 任务

- 建立前端、网关、Nacos、imAgent、模型和数据库的测试环境；
- 核对反向代理对 SSE 缓冲和超时的配置；
- 增加结构化日志、基础指标和错误告警；
- 编写启动、部署、回滚和数据迁移说明；
- 进行并发、长连接中断与优雅停机测试；
- 清理兼容字段并给出废弃时间表。

### 验收

- 完成一次真实客户端到模型再返回客户端的链路；
- 多实例时请求能通过 Nacos 和网关正常路由；
- 滚动重启不会产生大量悬挂运行；
- 已保存消息与客户端显示内容一致；
- 发布失败时可以回滚服务版本和数据库迁移。

## 10. 推荐的近期开发顺序

接下来最值得先做的五件事：

1. 固定消息和 SSE 契约；
2. 完成可信用户解析；
3. 用假模型写流式接口测试；
4. 打通前端 → 网关 → imAgent 的文本流；
5. 再开始设计数据库表。

不要在流式聊天尚未稳定时同时开发长期记忆、多 Agent 和任意代码执行。
