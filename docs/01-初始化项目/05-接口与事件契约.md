# 接口与事件契约

## 1. 契约现状

当前存在三套容易混淆的字段风格：

- 旧 Java AI DTO：`userId`、`msgType`、`imageUrl`、`personalityId`；
- 当前 Python 请求模型：`user_id`、`message_type`、`image_url`、`personality_id`；
- 网关可信身份：`user-info` 请求头。

迁移期间可以用 Pydantic alias 同时接收两种 JSON 命名，但响应必须尽快确定一种规范。以下文档以 `snake_case` 作为 imAgent v1 的推荐规范。

## 2. 通用规则

### 2.1 请求头

| 名称 | 来源 | 用途 |
|---|---|---|
| `Authorization` | 客户端 | 网关鉴权 |
| `user-info` | 网关 | 下游恢复当前用户，不允许客户端直连伪造 |
| `X-Request-ID` | 客户端或网关 | 可选；没有时由服务生成 |
| `Last-Event-ID` | 客户端 | 后续需要 SSE 断点恢复时使用 |

### 2.2 ID 与时间

- 所有雪花 ID 在 JSON 中使用字符串；
- 时间使用带时区的 ISO 8601，例如 `2026-09-10T18:30:00+08:00`；
- 数据库可保存 UTC，展示层负责转为本地时间。

### 2.3 普通响应

为兼容前端现有的 `res.data` 使用方式，建议统一响应包：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {}
}
```

错误响应示例：

```json
{
  "code": "CONVERSATION_NOT_FOUND",
  "message": "会话不存在或无权访问",
  "request_id": "req_01...",
  "details": null
}
```

业务错误不要一律返回 HTTP 200。推荐使用 400、401、403、404、409、422、429 和 5xx 表达类别。

## 3. 核心数据对象

### 3.1 AI 会话

```json
{
  "id": "conv_01...",
  "title": "新的对话",
  "personality_id": "10001",
  "status": "active",
  "created_at": "2026-09-10T18:30:00+08:00",
  "updated_at": "2026-09-10T18:30:00+08:00"
}
```

### 3.2 AI 消息

```json
{
  "id": "msg_01...",
  "conversation_id": "conv_01...",
  "role": "user",
  "message_type": "text",
  "content": "帮我分析这个项目",
  "personality_id": "10001",
  "status": "completed",
  "created_at": "2026-09-10T18:30:00+08:00"
}
```

`role` 推荐只允许 `user`、`assistant`、`tool`、`system`。客户端发送消息时只允许创建 `user` 角色；服务端生成其他角色。

`message_type` 推荐使用可读字符串而不是裸数字。若为了兼容当前前端保留 `1=text`，应在接口适配层转换，不让数字扩散到领域层。

### 3.3 Agent 运行

```json
{
  "id": "run_01...",
  "conversation_id": "conv_01...",
  "status": "running",
  "current_step": "model",
  "created_at": "2026-09-10T18:30:00+08:00",
  "completed_at": null,
  "error_code": null
}
```

## 4. 第一阶段接口建议

为了减少前端改动，第一阶段可继续使用现有 `/ai-message` 前缀。

| 方法 | 路径 | 用途 | 状态 |
|---|---|---|---|
| GET | `/ai-message/health/live` | 进程存活 | 规划 |
| GET | `/ai-message/health/ready` | 模型、数据库等就绪 | 规划 |
| POST | `/ai-message/conversations` | 新建 AI 会话 | 规划 |
| GET | `/ai-message/conversations` | 会话列表 | 规划 |
| PATCH | `/ai-message/conversations/{id}` | 改标题或归档 | 规划 |
| GET | `/ai-message/loadMessage` | 加载历史消息，兼容前端 | 前端已有入口 |
| POST | `/ai-message/sendMessage` | 发消息并返回 SSE | 建设中 |
| POST | `/ai-message/runs/{id}/cancel` | 停止生成 | 规划 |
| GET | `/ai-message/listPersonality` | 角色列表 | 前端已有入口 |
| POST | `/ai-message/createPersonality` | 创建角色 | 前端已有入口 |
| POST | `/ai-message/updatePersonality` | 更新角色 | 前端已有入口 |
| POST | `/ai-message/switchPersonality/{id}` | 切换角色 | 前端已有入口 |
| DELETE | `/ai-message/deletePersonality/{id}` | 删除角色 | 前端已有入口 |

历史消息接口至少增加：

```text
conversation_id: 必填
before_id: 可选，游标
limit: 默认 20，限制最大值
```

不能继续只按用户查询最近 20 条，否则多个 AI 会话的上下文会混在一起。

## 5. 发送消息请求

推荐请求：

```json
{
  "conversation_id": "conv_01...",
  "client_message_id": "client_uuid",
  "content": "请解释这段代码",
  "message_type": "text",
  "personality_id": "10001",
  "attachments": []
}
```

约束：

- `user_id` 不由客户端决定；
- `role` 固定为 `user`，无需客户端提交；
- `client_message_id` 用于网络重试时去重；
- 服务端校验会话属于当前用户；
- `personality_id` 省略时使用会话配置或默认角色；
- 文本长度、附件数量与总大小必须有限制。

## 6. SSE 事件

响应头至少应包含：

```text
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

不建议继续把任意文本直接拼成 `data:xxx`。使用 JSON 事件可以保留空格、换行，并为 Agent 工具状态扩展。

### 6.1 事件类型

| event | 用途 |
|---|---|
| `run.started` | 告知本次运行与助手消息 ID |
| `message.delta` | 追加文本片段 |
| `tool.started` | 工具准备执行 |
| `tool.approval_required` | 等待用户授权 |
| `tool.completed` | 工具执行结束 |
| `message.completed` | 完整消息已保存 |
| `run.failed` | 运行失败 |
| `run.cancelled` | 用户取消 |
| `done` | 流正常结束 |

### 6.2 示例

```text
event: run.started
data: {"run_id":"run_01","message_id":"msg_02"}

event: message.delta
data: {"message_id":"msg_02","delta":"你好"}

event: message.delta
data: {"message_id":"msg_02","delta":"，有什么可以帮你？"}

event: message.completed
data: {"message_id":"msg_02","content":"你好，有什么可以帮你？"}

event: done
data: {"run_id":"run_01"}

```

### 6.3 客户端解析要求

- 缓存不完整行，不能假设一次 `reader.read()` 正好对应一个 SSE 事件；
- 以空行作为事件边界；
- JSON 解码后再读取 `delta`，不能对正文调用 `trim()`；
- 处理 UTF-8 多字节跨 chunk；
- 收到失败、取消或连接断开时正确结束 loading 状态；
- 按 `message_id` 更新消息，不依赖数组索引；
- 支持心跳注释行，例如 `: ping`。

## 7. 幂等、取消与重试

- 同一个 `client_message_id` 重试时不重复落库或重复启动模型；
- 取消接口只允许会话拥有者取消正在运行的任务；
- 模型请求是否自动重试要按错误类型决定，已向用户输出内容后不能无脑从头重复；
- 工具写操作不自动重试，除非工具本身提供幂等键；
- SSE 断线后的第一阶段策略可以是“查询运行状态并重新拉取完整消息”，不必立即实现 token 级断点续传。

## 8. 契约测试清单

- camelCase 兼容输入与 snake_case 标准输入；
- 缺失或伪造身份；
- 访问其他用户会话；
- 重复 `client_message_id`；
- 中文、空格、Markdown 与代码块的 SSE 分片；
- 模型超时、限流、客户端中断；
- 工具事件顺序；
- 大于 JavaScript 安全整数范围的字符串 ID。
