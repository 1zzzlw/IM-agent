## 2. 推荐立即确认的技术决策

### ADR-001：imAgent 的业务边界

- 状态：建议采纳；
- 决策：imAgent 只拥有 AI/Agent/Vibe Coding 领域，普通 IM 继续由 Java/Netty 服务负责；
- 原因：避免复制成熟的账号、关系链和实时消息能力。

### ADR-002：身份来源

- 状态：建议采纳；
- 决策：业务用户 ID 只从网关注入的 `user-info` 获取；
- 结果：请求体逐步移除 `user_id`，服务端直连端口必须限制访问。

### ADR-003：AI 传输协议

- 状态：建议采纳；
- 决策：普通接口使用 JSON，单次生成使用结构化 SSE；
- 原因：符合现有前端入口，也能承载消息增量、工具状态、错误和完成事件。

### ADR-004：JSON 命名

- 状态：待确认；
- 推荐：imAgent 新契约使用 snake_case，迁移期通过 alias 接收 camelCase；
- 备选：为了整个 IM 前端一致继续使用 camelCase；
- 注意：必须选定一种标准响应，不要永久双写两套字段。

### ADR-005：AI 数据归属

- 状态：待确认；
- 推荐：AI 会话、消息、角色和运行记录迁移到 imAgent 独占写入；
- 简化方式：可以继续使用同一个 MySQL 实例，但表所有权必须唯一。

### ADR-006：Agent 编排

- 状态：建议采纳；
- 决策：基础聊天先保持简单；需要工具、状态恢复和审批时再使用 LangGraph 图；
- 原因：`create_agent()` 可以快速验证模型，但完整产品需要显式状态和运行记录。

### ADR-007：Vibe Coding 执行位置

- 状态：必须在开发前确认；
- 方案 A：工具在 Electron 本机执行，Python 负责编排，适合操作用户本地项目；
- 方案 B：项目上传到服务器沙箱执行，隔离更强，但涉及上传、存储和环境构建；
- 不建议：中心服务器直接访问客户端声明的任意绝对路径。

如果产品主要面向个人桌面端，第一阶段更适合方案 A：Electron 主进程提供受控文件/命令工具，用户本机执行，并由 UI 展示审批。Python 服务只生成结构化调用请求。

## 3. 数据表初稿

仅用于明确实体，不应在接口和迁移策略确认前直接建表。

### `ai_conversation`

- `id`：字符串形式雪花 ID；
- `user_id`：会话拥有者；
- `title`；
- `personality_id`，可空；
- `status`；
- `created_at`、`updated_at`、`archived_at`。

### `ai_message`

- `id`；
- `conversation_id`；
- `user_id`；
- `role`；
- `message_type`；
- `content`；
- `personality_id`，可空；
- `client_message_id`，用户范围内唯一；
- `status`；
- `created_at`。

### `ai_personality`

- `id`、`user_id`；
- `name`、`avatar_url`、`system_prompt`；
- `is_active`、`is_preset`；
- `created_at`、`updated_at`。

### `agent_run`

- `id`、`conversation_id`、`trigger_message_id`；
- `status`、`current_step`；
- `model_name`；
- `started_at`、`completed_at`；
- `error_code`、`error_message`。

### `agent_tool_call`

- `id`、`run_id`；
- `tool_name`；
- `risk_level`；
- `arguments_summary`；
- `approval_status`；
- `execution_status`；
- `started_at`、`completed_at`。

敏感工具参数和完整文件内容不应无条件写入日志或数据库。

## 4. 需要产品层确认的问题

1. AI 会话是否继续出现在普通会话列表中，还是拥有独立入口？
2. 一个 AI 会话能否随时切换角色，还是角色在创建会话时固定？
3. “开启新的对话”是否保留旧历史，默认标题如何生成？
4. 旧 Java AI 消息和角色是否必须迁移？
5. Vibe Coding 操作本地目录还是云端仓库？
6. 哪些写操作必须逐次确认，用户能否对当前任务临时授权？
7. 模型提供商是否固定为一个 OpenAI 兼容接口，是否需要用户自带 Key？
8. 是否需要按用户统计 token、费用或每日配额？
9. 第一阶段是否支持附件，还是只支持纯文本？
10. 原路线“实时建模输”具体指什么产品能力？

这些问题不阻塞 M0 和 M1，但会影响数据库、客户端交互和 Vibe Coding 架构，应在进入对应里程碑前确定。
