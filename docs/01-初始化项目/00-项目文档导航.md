# imAgent 初始化项目文档导航

## 1. 这组文档解决什么问题

`imAgent` 是现有 IM 系统中新拆出的 Python AI/Agent 服务。现阶段的目标不是重做一套聊天系统，而是在复用现有账号、鉴权、网关和会话入口的基础上，逐步提供：

1. AI 基础聊天；
2. Agent 基础能力；
3. Vibe Coding；
4. 后续的多模态、实时建模与长期记忆。

这组文档用于统一项目边界、目标目录、接口契约和第一阶段实施顺序。文档中的状态标记含义如下：

| 标记 | 含义 |
|---|---|
| 已有 | 当前代码中已经存在入口或实现 |
| 建设中 | 已有部分代码，但尚未形成可用闭环 |
| 规划 | 推荐后续实现，当前不能视为已完成 |
| 远期 | 暂不进入第一阶段开发 |

## 3. 当前结论摘要

- 前端已经把 AI 会话作为 `conversation.type = 2` 接入会话列表，并提供独立 AI 聊天页面。
- 前端通过统一 HTTP 入口访问 `/ai-message/**`；网关已将该路径路由到 Nacos 服务 `im-agent`。
- 网关负责验证令牌，并向下游写入 `user-info` 请求头。
- Python 服务已经具备 FastAPI 入口、模型客户端、Nacos 注册/注销和 `/ai-message/sendMessage` 路由骨架。
- 当前发送接口等待模型完整生成后返回字符串，尚未形成前端需要的 SSE 流式闭环。
- 历史消息与个性化角色的前端入口已经存在，但 Python 服务尚未实现相应接口与持久化。
- 工作区注册和 `list/read/write` 本地文件工具已有初版代码；真实模型工具调用、审批、审计和多实例状态共享仍待运行验证与完善。

## 4. 第一阶段推荐结果

第一阶段结束时，用户应能在现有 Electron 客户端内：

1. 登录后进入 AI 会话；
2. 创建或切换 AI 会话；
3. 发送文本并稳定接收流式回复；
4. 重新打开页面后加载历史消息；
5. 选择一个个性化角色进行对话；
6. 看到 Agent 工具执行的结构化状态；
7. 在明确授权的本地工作区中完成一次“读取项目、生成修改、预览差异、确认应用”的 Vibe Coding 任务。

第一阶段不追求复杂多 Agent、自主长期运行、视频通话或完整长期记忆。先把单服务、单会话、单任务链路做稳定，再继续扩展。
