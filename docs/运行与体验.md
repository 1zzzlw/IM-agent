# 运行与体验

界面预览：[人物创建](预览/人物创建.png)、[朋友圈](预览/朋友圈.png)。截图来自 Electron 页面回归，使用测试人物与测试动态，展示实际渲染的界面，不是正式账号或真实模型生成记录。

## 启动人物服务

1. 保留已经创建的 25 张 `imagent_` 表。空数据库才执行 `sql/imagent_init.sql`，不要重复建表或删除普通 IM 数据。
2. 根据根目录 [.env.example](../.env.example) 在项目 `.env` 配置 MySQL 和默认文字模型。已有文件保留原值、补充配置即可。运行 `uv sync`，然后运行 `uv run python main.py`。
3. 沿用 IM 网关时开启 Nacos，网关已有 `/ai-message/** → im-agent` 路由。独立开发可配置 `NACOS__ENABLED=false`，直接调用本机 9090 端口。
4. 在桌面端或手机端打开 AI 伙伴，使用系统默认模型即可输入简单期望并从完整候选中选择人物。需要个人覆盖时，再通过界面保存并选择模型。

原先只有基础“微光”的用户，会看到首次完整创建入口。选择后保留原世界、已有聊天和记忆，只完成尚未进行的正式人物创建。已经完成正式创建的人物不能借此重复改写。

经 Nginx 访问时，`/ai-message/person/candidates` 完整生成候选后才返回 JSON，可能超过普通接口的 30 秒等待。`IM-SpringCloud/nginx-1.28.2/conf/nginx.conf` 已将它与 `/ai-message/sendMessage` 一起匹配 AI 长任务规则，读取超时为 300 秒，并关闭代理自动重试；普通接口仍为 30 秒。配置部署后需先执行 `nginx -t`，再执行 `nginx -s reload`。前端等待时间更长也不能阻止中间代理提前返回 504。

仓库附带的 Windows Nginx 使用 `worker_processes 1`，避免高核数机器的 `auto` 配置在热重载时触及进程数上限。[Nginx 官方 Windows 说明](https://nginx.org/en/docs/windows.html)也指出多 worker 中只有一个实际处理工作；Linux 部署的 worker 数按其运行环境另行设置。

常用服务端配置示例，密钥填写自己的值：

```dotenv
DATABASE__HOST=127.0.0.1
DATABASE__PORT=3306
DATABASE__USER=root
DATABASE__PASSWORD=你的数据库密码
DATABASE__NAME=你的数据库名称
MODELS__DIALOGUE__BASE_URL=你的兼容模型接口地址
MODELS__DIALOGUE__MODEL=你的文字模型名称
MODELS__DIALOGUE__API_KEY=你的模型密钥
MODELS__DIALOGUE__TEMPERATURE=1
NACOS__ENABLED=false
REDIS__ENABLED=false
```

模型配置在后端进程启动时读取；修改 `.env` 后重启后端，桌面端和手机端共用同一份配置。直接导入后端模块时也固定读取项目根目录 `.env`，不依赖终端的当前目录；同名进程环境变量优先于文件。

### 给四个 Agent 分配模型

只配置上面的 `MODELS__DIALOGUE__*`，四个 Agent 即可使用同一文字模型。需要区分时按槽位填写，例如：

```dotenv
# 省略 BASE_URL 和 API_KEY 时，共用 DIALOGUE 的地址与密钥。
MODELS__DIALOGUE__MODEL=你的对话模型
MODELS__MEMORY__MODEL=你的记忆模型
MODELS__MEMORY__TEMPERATURE=0.3
MODELS__RETRIEVAL__MODEL=你的提取模型
MODELS__EVENT__MODEL=你的事件模型

# 某个槽位使用另一服务时，为它配置独立连接。
MODELS__EVENT__BASE_URL=https://你的另一服务/v1
MODELS__EVENT__API_KEY=你的另一服务密钥
```

每个槽位都支持 `MODEL`、`BASE_URL`、`API_KEY`、`TEMPERATURE` 和 `PROVIDER`。`MODEL` 留空表示不启用该环境槽位；其余字段只在槽位启用后生效。`PROVIDER` 默认 `custom`，用于 OpenAI 兼容接口；也支持已有的 `openai`、`deepseek`、`mimo`、`ollama:local`、`ollama` 适配。指定这些供应方时沿用适配器的预设地址，自定义地址请选择 `custom`。

只有对话语言模型允许用户切换，顺序为：本次明确 `configId` → 个人 dialogue 绑定 → `MODELS__DIALOGUE__*` → 管理员公共 dialogue 绑定；均未配置时提示模型未配置。

提取、记忆、事件及所有多模态槽位固定使用服务端 `MODELS__槽位__*`，未配置时查询管理员 `system` 绑定；辅助文字槽位仍未配置时，使用无用户的服务端默认对话方案，不继承个人选择。多模态不使用文字模型兜底。已经选中的固定配置失效会报错，不悄悄更换模型。

如果以前通过界面选过个人聊天模型，测试对话环境默认时先切回系统默认。旧的个人辅助/多模态绑定现在不再生效，无需逐项解除。若已有管理员公共对话方案，又想用环境文件覆盖它，填写 `MODELS__DIALOGUE__MODEL`。环境配置无需插入模型表，也不会把文件中的密钥写入聊天或模型配置返回。

单实例负责当前后台生命周期。不要同时启动多份开发服务管理同一个世界；多副本部署所需的调度归属与跨进程即时通知仍需单独完善。

需要语义记忆检索时，再配置 `EMBEDDING__NAME`、`EMBEDDING__BASE_URL`、`EMBEDDING__API_KEY`。Chroma 默认保存在 `resources/storage/chroma/`，可通过 `RAG__PERSIST_DIR` 指定相对 resources 的目录。正文始终在 MySQL，索引不可用会退回关键词召回，不把索引失败当作记忆消失。

## 模型与多模态

多模态模型负责理解照片和原始声音，或按能力产生图片和声音。人物核心负责如何理解这些线索、形成感受和选择行为。多模态由服务端固定配置，与用户选择的对话语言模型分开。同一模型支持多项能力时可在多个服务端槽位重复填写。

| 配置项 | 用途 | 当前适配约定 |
| --- | --- | --- |
| 聊天 | 检索决策、角色评价和文字表达 | 兼容 `/chat/completions` 的文字模型，能按 JSON Schema 的说明生成 JSON |
| 记忆、提取、生活 | 为对应后台或辅助过程设置固定模型 | 只使用服务端 ENV 或 system 绑定；均未配置时使用服务端默认，不跟随用户切换 |
| 识图 `vision` | 直接理解照片 | 支持文字与 `image_url` 内容块的多模态聊天接口 |
| 图片 `image` | 自拍、生活照、绘画与动态图片 | `/images/generations` 返回 `b64_json`；后续同一人物图片使用 `/images/edits` 参考图 |
| 语音识别 `asr` | 短语音和通话内容转写 | `/audio/transcriptions`，支持提交的 WAV、WebM、Ogg 或 MP3 |
| 角色声音 `tts` | 短语音和通话发声 | `/audio/speech` 返回 WAV，支持角色声线标识及表达 instructions |
| 声音情绪 `audio_emotion` | 从语速、笑声、哽咽等原始声音线索理解情绪 | 支持 `input_audio` 的多模态聊天接口，且支持输入音频格式 |

只有接口地址与模型名还不足以保证兼容。选择的模型需要支持对应输入和输出；不能因为一个模型会识图，就认为它也能生成图片或声音。能力缺失会提示，不自动替换为其他供应方。

多模态也可直接在 `.env` 中按需启用，无需先在界面建模型配置与绑定：

```dotenv
MODELS__VISION__MODEL=你的识图模型
MODELS__IMAGE__MODEL=你的图片生成模型
MODELS__ASR__MODEL=你的语音识别模型
MODELS__TTS__MODEL=你的语音合成模型
MODELS__AUDIO_EMOTION__MODEL=你的原始音频理解模型
```

这些槽位同样支持独立的 `BASE_URL`、`API_KEY` 等字段，留空时共用 `DIALOGUE` 连接。同一模型确实支持多项能力时可以重复填写；没有对应能力则将该槽位的 `MODEL` 留空，系统会提示缺少能力。普通文字模型不会自动被视为多模态模型。

语音转写与声音情绪分别处理。声音情绪能力不可用时可以保留转写，但会说明尚未获得声音线索，不能把文字情绪判断冒充声音理解。桌面录音通常是 WebM，手机使用 WAV，需选择支持相应格式的服务。

人物声线标识随人物保存，换模型不改写人物。新模型不支持该声线时需要更换为兼容方案；当前没有完成跨供应方声线克隆。图片使用外貌描述与参考图保持连续，实际一致性取决于所选图片模型，仍需人工检查。

通过界面提交的私有密钥保存到服务端加密凭据文件，数据库只保存引用；在 `.env` 填写的密钥直接从服务端环境读取。桌面端继续保留本机 safeStorage 缓存。运行数据默认在 `resources/storage/runtime/`，可以用 `IMAGENT_RUNTIME_DIR` 更改；备份或迁移时保留加密文件与 `secret.key`，也可以用 `IMAGENT_SECRET_KEY` 指定 Fernet 密钥。密钥不会放入消息、任务或公开配置返回。

如果环境配置了 HTTP 代理而模型调用反复超时，可先验证供应方是否能直连；确认可以时，将该模型服务域名加入 `NO_PROXY`，保留其他服务原有代理配置。此前默认模型的两轮集成验证在直连条件下通过，完成 4 条消息保存与上下文接续，约耗时 89 秒；这次配置整理没有重复进行真实供应方调用。这个小样本不代表当前模型已经达到流畅聊天或实时语音的速度。

## 体验人物核心

建议使用同一人物依次检查：

1. 普通问候，观察它的说话方式；不要要求每次都回忆旧事。
2. 告诉它一个喜好，等待后台记忆任务完成后继续聊天，再询问相关事情；检查记忆是否有来源。
3. 纠正旧信息，观察后续是否采用新信息；没有找到的往事不应被补造成真实回忆。
4. 用不同态度交流，观察情绪延续、关系和表达意愿；沉默与技术失败应当分别处理。
5. 调整生活窗口，观察无新事件时活动仍能继续，重要事件则可能中断等待中的回复。
6. 查看朋友圈并点赞评论，观察后续理解是否承接互动。不可见动态不应出现在用户列表中。
7. 约定稍后的共同活动。后台在到时后重新判断是否赴约；只有实际参与才记录共同过程，半小时活动不会在几轮消息中立即完成。
8. 切到另一设备，继续同一个人物和聊天；隐藏在线、输入和已读状态后，角色只获得允许公开的线索。

记忆评分、淡忘速度、成长间隔和情绪随机性是首版工程机制，不是已经证明的心理学规律。`resources/psychology/` 已有情绪评价、调节及人格情境的有来源研究摘要，配合工程使用边界进入角色评价上下文；仍是少量人工整理的材料，尚无独立的专业资料检索。说明与出处见 [资源说明](../resources/README.md)。人物是否自然、是否出现不合理反应，需要用持续交流案例继续评价。

## 语音通话

先设置 ASR、TTS 和人物声线。用户发起呼叫，人物按实际状态和关系决定是否接听。接通后持续监听，用户说完一个片段再处理并生成语音；用户插话时停止旧播放，并作废旧输出。

当前采用连续音频轮次，包含转写、人物推理和语音合成的等待，不是供应方原生端到端实时音频协议。延迟取决于模型和网络。播出确认按句段记录，未播放的尾句不进入共同记忆；被打断句段中的逐字对齐、细粒度已听内容与声学质量还需后续完善。桌面和手机已接入流程，真实麦克风、扬声器回声、权限与不同供应方需要实机验证。

## 管理员

配置 `IMAGENT_ADMIN_TOKEN` 后，用 `X-Agent-Admin-Token` 请求头访问管理员接口。普通用户界面不提供人格修改、记忆浏览、清理历史和重建操作。

- `GET /ai-message/admin/person?userId=...`：查看人物内部快照、有效记忆和最近任务。
- `POST /ai-message/admin/operations`：`history_clear` 只清理用户可见历史；`intervention` 缓解感受及指定经历的影响、可调整关系；`recreate` 归档旧世界并允许重新创建。
- `PUT /ai-message/admin/model-default`：为指定 `slot` 设置服务端模型方案和受控凭据。ENV 专用槽位优先；仅对话允许个人覆盖，其他槽位固定供后台或媒体处理使用。需要 `requestId`、`reason`、配置名称、供应方与模型名称等参数。
- 每次写操作提供 UUID `requestId` 和 `reason`，保留审计。干预不会删除事实与记忆。

## 验证边界

后端普通回归、独立 MySQL 中的约束与事务、模拟模型的完整人物链路、真实模型接口调用、Electron 页面回归与人工长期体验是不同的验证层次。测试中使用模拟模型只验证程序协作，不证明人物反应已经自然。

本次检查结果：

| 范围 | 结果 |
| --- | --- |
| 后端回归 | 71 项中 70 项通过，真实模型项跳过；包含独立 MySQL、真实 Chroma 索引、四 Agent 协作、唯一 ENV 模型配置、固定能力不随个人切换及旧绑定兼容 |
| 真实模型小样本 | 此前单独开启后，两轮对话与 4 条消息保存通过；这次配置整理未重复调用真实供应方 |
| 桌面端 | 修改范围的 ESLint、完整类型检查、生产构建与 8 组 Electron 页面场景通过 |
| 手机端 | 57 项测试通过，1 项可选视觉导出跳过；新增人物相关静态检查通过 |
| 数据结构 | 原有 25 表 SQL 未修改，设计文档内建表语句与初始化脚本一致 |

真实语音设备、不同多模态供应方的兼容性，以及长时间运行的人物行为质量尚未完成实机或长期验证。通话采用连续音频轮次，并未将它标作供应方原生端到端实时音频协议。

书籍或课程的自主获取、用户直接与虚拟伙伴聊天、AI 主动拨打电话保留为后续扩展。专业知识资料、跨供应方声线与图像一致性、长期人格变化的质量，也不能仅凭接口接通认定完成。
