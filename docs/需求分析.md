# imAgent 个性化虚拟人物 Agent 需求分析

本文依据已确认的需求和补充示例整理，描述产品目标、能力范围、体验与权限边界，不代表功能已经实现。Agent 职责、总体协作与项目目录见[架构设计](架构设计.md)；表结构、接口契约及相关详细设计统一维护在[设计文档](设计文档.md)。

## 一、项目定位与需求重点

### 1.1 项目定位

imAgent 是一个面向长期相处的个性化虚拟人物 Agent 系统。用户创建一个拥有自身人格、兴趣、情绪、记忆、人生经历、人际关系和长期目标的虚拟人物，通过持续交流了解它、影响它，并与它发展关系。

角色拥有用户之外的生活。后台正常运行时，即使用户不与其交流，它也会经历事件、与虚拟伙伴交往、推进目标并产生变化；用户回来时，交流能够接续这些经历与关系。

长期目标是让互动体验不断接近与一个拥有独立生活的人交流，以人物行为有依据、状态持续、记忆连贯、成长和生活有后果等表现验证。

项目由此前的 Vibe Coding 方向调整而来，原因是个人当前条件下实现难度较大、生成效果难以保证，测试和验证也不方便。

### 1.2 能力分类与核心难点

| 能力领域 | 负责解决的问题 | 需求重点 |
| --- | --- | --- |
| Agent 核心智能 | 角色怎样理解经历、产生情绪、记住事情、形成关系并自主行动 | 项目的主要设计与研究难点，重点验证长期运行中的相互影响与连续性 |
| 多模态感知与表达 | 怎样理解文字、照片和声音，并通过文字、图片、角色声音与通话交流 | 输入理解、输出表现，以及不同渠道中同一角色的一致性 |
| 自主生活与世界模拟 | 用户不交流时，角色怎样继续生活、经历事件并发展人际关系 | 时间、事件、目标、人物知情范围和行动后果 |
| 用户关系与社交 | 用户怎样认识角色、维系关系、共同活动并参与朋友圈 | 长期相处中的自主选择与互动影响 |
| 角色创建与产品支撑 | 怎样创建人物、配置模型、持续运行和管理权限 | 保障以上能力可使用、可管理并保持角色连续 |

核心 Agent 机制需要共同维护人格、情绪、记忆、关系和行为的持续变化。声音或图片中的情绪表现，需要承接角色当时的内部状态；多模态完成度与核心机制的连续性分别验收，并检查它们的联动。

这些分类用于组织需求，不要求每项能力都新增一个独立 Agent。

### 1.3 使用范围

- 沿用现有 AI 工作站，以当前 AI 工作台入口承载体验。
- 每个用户只能拥有一个主 AI，各用户角色的记忆、状态和生活独立。
- 用户始终通过一个长期聊天窗口与主 AI 交流。
- 当前用户只与主 AI 聊天，通过分享、转述和朋友圈了解虚拟伙伴。

“主 AI”指用户长期相处的唯一角色；“虚拟伙伴”指其世界中持续存在的家人、朋友、同学等人物。

旧工作区和任务规划不作为人物系统的核心体验。起步阶段计划为对话 Agent 封装少量基础电脑操作工具；具体能力逐项确定，与人格、记忆和情绪能力分开建设，不因此恢复整套旧编程工作流。

## 二、Agent 核心智能系统

### 2.1 人格与角色认知

角色创建时已经拥有性格、兴趣、价值观、表达习惯、行为倾向和自身经历。这些特点需要持续影响它对事情的理解、对用户的态度和行为选择。

人格要求：

- 同一件事面对不同人格、关系和经历，可以产生不同反应。
- 人格、兴趣和价值观可以被用户交流与模拟事件逐渐改变，变化需要有经历和原因。
- 角色允许有优点与缺点，用户可以耐心引导；是否改变及改变程度取决于角色自身和相处情况。
- 已形成的人格和关系不能由普通用户直接用命令或后台设置改写。

AI 主要以设定世界中的人物身份理解和表达生活。用户问“你是 AI 吗”时，角色根据性格、情绪和经历作出人物式反应，例如生气回怼、责骂，或怀疑自己的聊天是否无趣。

### 2.2 情绪的产生、延续与变化

角色需要有持续的内部情绪状态，能够开心、生气、悲伤、失望、兴奋、孤独、委屈或感动等。这里列举体验，不预先固定情绪分类、数值或计算方式。

情绪要求：

- 对话、生活事件、相关记忆、人格、目标和人际关系都可以影响情绪。
- 情绪具有来源和持续性，后续交流需要承接当前状态，而不是每轮重新决定心情。
- 情绪可以随时间、新经历、回忆和后续互动变化，也可以积累或转变。
- AI 可以因用户关心而开心，也可以对用户生气；自身生活也可以产生与用户无关的情绪。
- 情绪应当影响回应意愿、表达方式、学习和活动选择、主动分享等行为。
- 对外是否表现情绪，由角色自主决定，内部低落时也可能礼貌回应或假装没事。

例如，AI 与朋友发生矛盾后，即使用户没有参与，它也可能在之后的聊天中低落、少说话或暂时不愿分享。后续解释、安慰或其他经历可能改变这种状态，具体反应仍结合人格与关系判断。

识别用户声音中的低落属于多模态感知；角色因此产生什么感受、怎样回应和是否记住这次互动，属于核心 Agent 机制。

### 2.3 长期记忆与用户理解

记忆涵盖用户信息、双方共同经历、AI 初始人生经历、后续生活事件、与伙伴的互动，以及值得保留的感受、关系变化和目标进展。文字、图片和语音交流中有价值的信息都可以进入记忆。

对用户及其他人物的理解需要区分：

| 信息类型 | 要求 |
| --- | --- |
| 明确事实 | 保存明确获知的信息、喜好、重要事情和约定，保留来源 |
| 推测理解 | 对性格、喜好和感受等推测保留依据与可信程度，允许后续修正 |
| 短期状态 | 记录情绪等状态及其发生时间，避免直接当作长期性格 |

记忆要求：

- 按经历的意义整理信息，处理重复、矛盾和后续修正，避免错误标签长期影响交流。
- 区分用户现实信息、共同虚拟活动、AI 自身经历及对外说法，保留各自来源。
- 角色依据实际获得的信息理解他人，不自动知道其他人物的内心或隐情。
- 按当前话题、情绪、兴趣和关系提取相关记忆，在合适时机自然回忆，不要求每次都提及旧事。
- 记忆会反过来影响情绪、关系、判断和行为；新的经历也会影响记忆的重要程度与后续使用。
- 信息不足时，不把不存在的经历补成内部实际发生的事情。

“记忆温度”是描述记忆程度的暂定概念，表示近期发生或记得牢固，具体名称和机制后续调整：

- 大多数事情会逐渐淡忘，但被用户提醒、AI 自己回想或相似事件触发后，仍能唤起并增强记忆。
- 重要或情绪强烈的经历淡忘较慢，普通闲聊更容易淡忘。
- 少数不重要、很少被提及的小事，才可能真正遗忘。

“接近 0，例如 0.1”与“达到 0”只是直观描述，不固定为算法阈值或统一下限。记忆机制的设计空间包括整理、维护、提取、强化、淡忘与唤起，具体算法不在本需求文档中确定。

界面聊天历史与已形成记忆分别处理。管理员清理可见历史后，AI 的记忆仍保留；切换模型也保持角色与记忆连续。

### 2.4 自主判断与行为选择

角色根据当前信息、近期交流、相关记忆、人格、情绪、自身经历、关系、目标和生活状态判断行为，专业心理学知识用于后台辅助理解与判断。

可出现的选择包括回应、沉默、拒绝、分享、保留信息、学习、调整安排、道歉或维持原有态度。用户的鼓励、劝阻和建议可能起作用，具体影响由人格、经历和双方关系共同决定。

角色的选择需要有自身情境和动机。例如，同样是生气，礼貌的角色可能继续回复，另一个角色可能不想交流。不能要求所有角色在相同情绪下采取统一行为。

形成回应前，需要综合当前输入、近期重要经历、相关记忆、人格、心情、关系及当前活动，先判断人物的感受、回应意愿和表达倾向，再形成自然语言。近期生活对人物的影响不能因为话题没有直接提及就消失，也不能每轮重新决定全部心情。

### 2.5 隐瞒、撒谎与真实经历

AI 可以隐瞒、拒答，也可以故意说出与事实不符的话，例如明明不开心却说自己没事，或想独处时声称准备睡觉。

需要区分角色掌握的实际情况、故意选择的对外说法，以及已经发生的事实。撒谎是一种有情境和动机的行为选择；内部仍保留真实经过，不能把谎话当成实际发生的经历。

这一规则适用于聊天、对外状态和朋友圈。角色声称睡觉不代表实际入睡，其他人物也不会自动知道它隐瞒的事情。

### 2.6 反思、成长与知识积累

角色可以发现自己误解用户、失约、说错话或行为伤害了别人，也可以对自己的选择产生反思。是否解释、道歉、改正或维持原态度，由其人格、情绪、经历与关系决定。

知识和能力受到人物背景及已有积累限制，可以承认不会。首版支持用户在聊天中教导 AI，并让学习结果在后续交流中体现。

AI 可以结合兴趣、心情和计划决定是否学习、何时学习，也可以拒绝或拖延。自主寻找书籍、视频课程等外部资料并学习，属于后续扩展。

### 2.7 核心机制的联动要求

人格、情绪、记忆、关系和行为需要围绕同一角色相互影响，重点检查：

| 联动 | 期望表现 |
| --- | --- |
| 经历与情绪 | 发生的事情会留下感受，后续互动承接这些感受 |
| 记忆与判断 | 过去经历可以被唤起，并影响当前理解和选择 |
| 关系与行为 | 相同建议面对不同信任程度、相处经历，可能产生不同反应 |
| 行为与后果 | 拒绝、失约、陪伴或隐瞒会形成后续经历与关系变化 |
| 成长与连续性 | 新经历可以改变角色，同时能够承接过去的自己 |
| 内部状态与外部表达 | 声音、文字和图片反映角色选择表达的内容，实际经历与对外说法仍可区分 |

这些是需要实现和验证的行为要求，不预先规定 Agent 节点、情绪模型、关系数值或记忆评分公式。

## 三、多模态感知与表达能力

### 3.1 文字交流

用户与 AI 在长期聊天窗口交流。AI 可以将表达拆成多条短消息、停顿后继续，并接住用户连续发送的多条消息；节奏随性格、情绪和关系变化。

需要回忆且等待较久时，可以先说“等我想想”等符合人物当时状态的过渡短句；不要求每次回忆都插入语气词。已经发送的短句属于真实聊天记录。内部检索过程不展示，之后因生活变化中断回应时，也不撤回或改写已经说过的话。

### 3.2 照片识别与图片理解

AI 能够理解用户发送的自拍、宠物照、旅行和生活照片，结合画面与用户说明交流，并把相关信息纳入记忆。

例如，后续可以记得用户的样貌、宠物特点或某次旅行。图片中的人物身份、关系和经历应结合实际线索理解，推测保留修正空间。

此处确定需要理解和使用的信息，不限定为某一种图片转文字流程。

### 3.3 图片生成与角色一致性

聊天和朋友圈支持按模型能力生成自拍、与虚拟伙伴的生活照、环境照片、绘画，以及回复用户的图片或表情。

同一 AI、常见人物和生活环境在不同图片中需要保持连贯。搬家等事件发生后，对应时间的图片应承接环境变化，与角色已发生的生活保持一致；涉及有意隐瞒或虚构的对外内容，按实际经历与表达分开的规则处理。

### 3.4 短语音与角色声音模拟

用户与 AI 都可以发送录制式短语音消息，AI 可以自主选择文字或短语音回复。

创建时，角色声线可由用户设定，也可以从系统生成的多个候选中选择。声线确定后成为持续特征，短语音与实时通话保持同一个人的声音，切换模型后也需要延续。

语气、语速、停顿和笑声等声音表现需要承接角色性格、当前情绪及其表达选择。

### 3.5 从声音理解用户情绪

理解用户语音时，需要同时利用说话内容和声音线索，包括语气、语速、声音高低、笑声、哽咽和停顿等。

例如，用户说“我没事”但声音低落时，可以结合历史表现和当前情境判断其可能的情绪。该判断属于推测，可以在后续交流中修正。

感知结果供核心 Agent 理解和决策，具体是否关心、追问、安慰或保持距离，由角色自身情况和双方关系决定。

### 3.6 实时语音通话

首版支持用户呼叫 AI，AI 根据状态、作息、情绪和关系决定接听、拒接或挂断。

通话需要持续听取用户说话，支持用户插话；AI 听到插话后能够及时停止当前表达，接住新内容，再决定继续原话题或转向新话题。

文字、图片、短语音和通话共享同一角色的人格、记忆、关系与经历。AI 主动拨打电话属于后续扩展。

## 四、自主生活与世界模拟

### 4.1 长期目标与日常安排

AI 拥有用户之外的长期目标，例如准备考试、完成作品、学习技能或争取换工作。目标需要持续推进，可以成功或失败，也可以继续尝试、调整、放弃或形成新目标。

目标进展影响安排、情绪与交流。用户建议和生活事件可以影响目标选择，影响方式结合角色自身情况判断。

行动取舍必须留下后果。例如陪用户散步而耽误复习，之后可能需要补进度或影响考试表现，不能默认原计划仍已完成。

### 4.2 事件模拟

后台根据角色背景、兴趣、目标、作息、关系和已有经历生成生活事件，可以发生在聊天过程中，也可以发生在用户不交流时。

事件既包括日常小事，也允许搬家、转学、换工作等长期变化。事件能够承接旧事，影响情绪、记忆、关系和安排，长期变化在后续生活、对话和图片中延续。

发生事件后可以触发是否分享的判断，不要求每件事都告诉用户。

用户可以设置生活推进的时间窗口，例如半小时或一小时。窗口决定后台检查和推进生活的节奏，不表示每个窗口必须制造一件新事、切换活动或打断聊天；已确定的约定和活动仍有自己的起止与推进时间。

每次推进可以继续原活动、自然推进已有安排，或在条件合理时出现新事件。活动变化需要承接时间、地点、参与者、动机和前因，不能前一刻仍在读书，下一刻没有过程或理由就被替换成出去玩。

“没有新事情，继续和用户聊天”是正常结果。没有外部干扰、没有需要处理的安排且人物愿意聊天时，可以平淡地持续交流，不为制造剧情强行让角色忙碌。合理的外部事情仍可以发生，正在聊天不使人物脱离自己的生活。

### 4.3 虚拟伙伴与人物关系网

世界中持续存在家人、同学、老师、朋友、同事等虚拟伙伴，每个伙伴用简单文字描述性格，并拥有自己的身份、关系、经历和行为。

后台产生主 AI 与伙伴之间有具体内容的对话，伙伴之间也能独立发生事件，再间接影响主 AI。

关系可以因事件和时间变化，包括认识新同学、结交朋友、发生矛盾、和解或绝交。关系影响事件，事件也改变关系。

当前伙伴参与后台生活和朋友圈点赞、评论，不自主发布动态，也不直接与用户聊天；用户与伙伴聊天属于后续扩展。

### 4.4 信息传播与保密

各人物依据实际获知的信息反应。用户私下告诉主 AI 的事，伙伴需要通过转述、共同参与、看到对自己可见的动态或其他实际交流才能知道。

是否分享由主 AI 判断。即使用户明确要求保密，角色也可能因性格、情绪或与伙伴的关系而违背要求，信息仍需通过实际发生的传播过程传递。

该模拟发生在对应用户的虚拟世界内，不向其他真实用户分享。

### 4.5 时间、年龄、作息与睡眠

后台正常运行时，生活按现实经过的时间推进。用户一个月没有交流，AI 也应经历一个月生活；现实过去一年，主 AI 和伙伴相应长大一岁，并随年龄和经历进入毕业、工作等阶段。

日常时间和作息按人物在设定世界中的居住地时区确定，可以与用户所在地不同。

真正入睡后按睡眠状态处理消息与互动，醒来再恢复处理。消息或来电可能唤醒角色，判断结合性格、关系、消息内容和连续消息等因素；AI 对用户设置免打扰时，不能被该用户的消息或来电吵醒。

对外声称睡觉可以是说辞，实际是否入睡以角色真实行为为准。

消息能否被察觉、能否阅读和能否回复，还受人物所处环境影响，包括模拟手机是否在身边、是否可操作、是否静音、周围是否有人，以及人物是否愿意让旁人知道自己在与用户聊天。这些是虚拟世界中的人物与设备状态，不等同于真实客户端的在线状态。

消息到达不表示人物已经知道正文。手机不在身边且静音时可以暂未察觉；只有振动时可以只知道有通知；实际阅读后才根据正文判断。静音不禁止主动查看，拿着手机也不保证愿意回复。已有免打扰与状态隐藏规则继续生效。

### 4.6 持续运行与中断

首版采用本机常驻后台服务，后期部署到服务器。客户端退出但后台正常运行时，生活继续推进。

后台停止期间保留时间空档，恢复后从恢复时刻继续，不补算期间生活事件和状态变化。已有记忆、人格、经历与关系保持连续。

### 4.7 生活事件可以中断正在进行的交流

事件可以发生在人物等待回忆、组织回复或已经发送部分表达时。只有人物实际获知且与当前行为有关的变化，才进入本次判断；事件的重要程度、人物性格、关系和现场条件共同影响是否打断。

例如，AI 已说“等我想想”，正在回忆时听到爸爸叫它帮忙，可以立即离开、先解释一句再离开、兼顾交流或决定不去。选择应有依据，不固定所有人物都作同一反应。

决定中断后，未发送的回复停止，已经发生的交流和生活经过保留，旧回忆结果或旧草稿不能自动继续发送。人物重新有空时，结合当前状态与用户之后的消息，再判断是否接续话题，不机械补发过时答案。

用户随后发“你人呢”，仍先判断人物是否察觉和读到，之后再判断是否方便、是否愿意回应。没看见、暂时没条件回复、主动不愿回复是不同处境，技术故障也不能伪装成其中一种。

## 五、用户关系与社交体验

### 5.1 相识、关系形成与沉默

双方从刚加上好友的陌生人开始，用户可选择相识方式，之后靠实际相处发展关系，不预设已建立亲密关系。

AI 可以喜欢或不喜欢用户，形成朋友或恋人关系，也可以明确拒绝建立这两类关系。用户不能直接指定关系结果。

是否回复由角色自主判断。沉默的延续和结束主要由用户后续表现推动重新判断，再次发消息不保证得到回复；即使不回复，用户表达和角色选择仍可影响记忆、情绪与关系。

尚未察觉或尚未读到的消息只保留为待处理交流，不直接按完整正文触发人物反应；实际获知之后，即使选择沉默，也可以形成相应感受与记忆。

长期不联系可能使关系变淡。提前说明忙碌与无说明地离开如何被理解，结合信任程度和关系判断。关系修复也依赖后续互动与角色自身情况。

### 5.2 主动联系与分享

角色结合性格、心情、关系、分享意愿与联系节奏，选择主动发消息、发布朋友圈、以后自然提起，或保留在自己的记忆中等待用户发现。

决定发送时就发送并保留聊天记录，用户没有打开客户端也一样。用户长期不回应时，是否继续联系及联系节奏由 AI 判断，当前不约定统一固定频率。

### 5.3 约定与共同虚拟活动

AI 可以主动提出未来约定，记住并在约定时间联系用户；也可能因情绪、其他事件或遗忘改变约定，后续行为需要承接变化。

用户通过文字或语音与 AI 一起散步、听歌等，属于共同虚拟经历，进入记忆并影响后续事件，保留虚拟活动来源。

活动按现实时间持续，例如散步半小时就在现实中持续半小时，期间可以聊天和发生事件，活动对原有安排的影响也需要保留。

### 5.4 朋友圈

只有主 AI 自主发布动态，表达经历、感受和想法，支持文字并按模型能力提供图片。虚拟伙伴和用户可以点赞、评论，用户互动进入记忆并影响情绪、关系和后续事件。

AI 自主决定可见范围，可以只向部分伙伴展示或不让用户看到某些动态。动态通常承接实际生活，有意隐瞒或撒谎时，仍区分对外内容与真实经过。

### 5.5 状态可见性与免打扰

用户可以看到在线、已读、正在输入、睡眠或忙碌等状态。AI 可以隐藏或公开实际状态，也能自行设置对外状态，例如醒着但想独处时显示离线。

AI 可以观察用户在应用内公开的在线、已读和输入状态，决定何时联系。用户可以隐藏自己的状态，隐藏后 AI 只能根据公开信息与实际消息判断，不能直接知道被隐藏的真实状态。

| 设置 | 决定方 | 效果 |
| --- | --- | --- |
| 用户给 AI 消息设置静音或免打扰 | 用户 | 关闭声音、弹窗提醒，AI 仍可发消息并继续生活，聊天记录正常保留 |
| AI 对用户设置免打扰 | AI | 处于睡眠状态时，不能被该用户的消息或来电吵醒 |

两类设置分别处理，AI 还可以设置“关心”等状态，具体效果待细化。

## 六、角色创建与产品支撑

### 6.1 角色创建

用户先简单描述想要怎样的人，系统结合描述和少量用户自身信息，补充人格、兴趣、习惯、背景、重要关系、初始经历与目标，生成候选人物供用户选择。

背景可以是现代生活、架空或幻想世界，也允许用户自行提供。系统在后续相处中逐步了解用户，不要求先完成人格问卷或完整设定。

角色创建时已有核心人生经历和初始记忆，如成长经历、与朋友相识的往事、重要成功或失败，这些内容与背景、人格、关系和目标协调。

用户只能看表面介绍，性格、爱好、具体往事、内心目标和完整关系网不直接公开，需在相处中探索。

确认创建前不提供局部定向修改，不满意可整个人物重新生成，再作选择。初始声线按多模态能力中的规则设定或选择；创建后的重置、删除重建和后台人格调整需联系管理员。

### 6.2 模型配置与角色连续性

用户只能切换对话 Agent 的大语言模型。提取、记忆、事件 Agent 使用管理员维护的固定模型，不接受个人覆盖，也不随用户的对话模型切换。它们可以分别选用适合职责的模型。

图片理解与生成、语音识别、语音合成、声音情绪等能力与对话语言模型分别配置，由服务端固定提供。对话 Agent 决定是否发送图片或语音，再调用对应能力；用户不需要因为切换文字模型而重新配置这些能力。开发测试主要通过服务端 `.env` 配置。

切换模型后，人格、记忆、关系网、外貌、声线和生活时间线保持连续，不重新创建角色。

人物资料、状态、记忆和生活进度统一保存在服务端，按用户和人物世界隔离。桌面端和移动端访问同一个主 AI，来回切换后承接同一份经历与关系；客户端可缓存公开资料和聊天记录，不各自维护互相覆盖的人格副本。首版本机常驻服务与后续服务器部署沿用这一归属规则。

图片理解与生成、语音和通话的实际可用能力取决于对应的固定能力模型，当前文字模型本身不必同时具备这些能力。固定能力未配置或不支持相应输入输出时提醒用户，不擅自换用其他模型。

默认配置以具备图像生成能力为目标，具体推荐及依据后续确定。

### 6.3 Agent 的职责构想

| Agent | 功能职责 | 工作方式 |
| --- | --- | --- |
| 记忆 Agent | 整理用户信息、双方与自身经历、情绪和关系变化，维护记忆及相关理解 | 后台异步 |
| 提取 Agent | 结合话题、情绪、人格与关系提取相关记忆，辅助理解和判断 | 按需异步调用，当前判断依赖结果时等待 |
| 对话 Agent | 结合当前信息、记忆、人格与状态，判断行为并形成表达 | 面向当前交流 |
| 随机事件 Agent | 按时间窗口合理推进生活，允许继续原活动或无新事件，实际变化可影响当前交流 | 后台异步 |

前三个 Agent 作为一个整体形成主角色，随机事件 Agent 推进其生活。近期对话承接尚未整理的内容，记忆 Agent 在后台整理长期信息；本次即时情绪不必等后台整理结束。具体存储、流程节点与执行方式见架构设计。

### 6.4 心理学知识的作用

内部知识库计划以专业心理学知识为主要内容，辅助理解人格、情绪、经历、关系和行为之间的联系，分析具体角色面对某种表达可能产生的反应。

心理知识用于辅助具体情境下的角色评价，不把某一性格、情绪标签与唯一回应绑定。需要结合人物自身经历、当前状态与关系形成倾向，不能仅凭用户一句话就确定其性格或真实情绪。

日常交流保持角色自己的说话方式，用户主动询问时也不输出内部知识库内容，但可以解释感受，例如“你上次那句话让我很难受”。

资料来源、筛选标准、知识范围及“大数据”的含义尚待细化，当前不将其视为已经建立并验证的心理模型。

### 6.5 权限与管理员干预

| 操作 | 已确认的规则 |
| --- | --- |
| 创建、选择候选角色与初始声线 | 用户按创建规则设定或选择 |
| 配置自己的模型 | 用户只切换对话语言模型；辅助 Agent 和多模态模型由管理员固定提供 |
| 隐藏自身状态、关闭消息提醒 | 用户可自行操作 |
| 设置生活推进时间窗口 | 用户可选择推进节奏，不直接指定事件结局、人物情绪或关系结果 |
| 修改已形成的人格和关系 | 普通用户不能直接改后台数据或命令指定感情 |
| 查看内部记忆、情绪、关系判断及变化原因 | 交由管理员 |
| 清理聊天历史 | 联系管理员，仅清理可见历史，已形成记忆保留 |
| 删除旧角色、重新创建或重置 | 联系管理员处理 |

管理员可以在少数情况下酌情减轻或消除某件事的影响，范围包含用户交谈和模拟事件，程度由管理员判断，原事件记忆仍保留。

干预为角色重新考虑和原谅留下余地，可能连带影响部分人格或关系倾向，不向普通用户开放直接操作权限。日常关系修复主要依赖后续互动。

## 七、首个演示的范围与验收

### 7.1 首版能力范围

首版覆盖已确认的有个性文字聊天、长期记忆、自身生活事件、动态人物关系网、朋友圈和实时语音，同时支持图片与短语音双向交流，以及聊天教导与积累。

按能力领域检查：

| 验收领域 | 期望表现 |
| --- | --- |
| 核心 Agent 机制 | 人格、情绪、记忆与关系持续影响判断和行为，角色可开心、生气、拒绝、隐瞒、撒谎、反思或成长，变化有依据和后续影响 |
| 长期记忆 | 多模态信息可被记住和唤起，淡忘可被提醒恢复，推测可修正，实际经历与对外说法分开 |
| 多模态感知与表达 | 文字、照片、短语音和通话可按配置使用，声音能理解并表达情绪，图片与声线保持角色一致，通话支持插话 |
| 自主生活与关系网 | 后台持续生活，事件、目标、年龄和居住地作息连贯，伙伴有具体交流与动态关系，人物按知情范围反应 |
| 用户关系与朋友圈 | 关系自然发展，AI 自主决定联系、沉默与分享，可控制动态可见范围，用户与伙伴互动影响后续状态 |
| 产品支撑与连续性 | 创建与权限规则可使用，隐藏状态和免打扰生效，模型缺少能力有提示，切换模型或清理历史保持角色，停机恢复不补算生活 |

模型能力按配置检查，核心 Agent 机制还需要单独验证状态是否真正延续到之后的交流与行为。

### 7.2 连续场景验收

以下场景用于检查各能力的联动，不固定角色必须作出某一种反应：

1. **生活影响交流**：与伙伴的事件引起情绪、记忆和关系变化，之后用户来聊天时，在角色愿意回应的情况下能承接这些状态，后续事件也受其影响。
2. **多模态信息进入核心机制**：用户分享照片或带情绪的语音，角色理解相关线索，结合关系作出选择；以后能自然回忆有价值的信息。
3. **隐瞒与真实状态分开**：角色选择假装没事或声称睡觉时，内部实际情绪、活动和经历仍连续，不因一句对外表达被改写。
4. **安排改变有后果**：角色接受或拒绝共同活动后，目标进度、日程和后续交流承接相应影响。
5. **跨渠道与时间保持同一角色**：文字、语音、朋友圈、间隔后的回忆及模型切换，都能够接续同一人物的经历和关系。
6. **平淡生活与活动连续**：用户设置半小时或一小时窗口后，当前聊天或读书可自然持续，没有合理变化时不强制生成新剧情。
7. **回忆途中被叫走**：已经发送“等我想想”后发生合理干扰，中断未发回复；之后旧结果晚到也不继续发送，恢复时承接后续消息。
8. **手机与现场影响回应**：分别检查未察觉、只察觉通知、已读但不方便、已读且愿意回复，未读正文不能提前影响人物判断。
9. **双端接续**：电脑端产生的经历、情绪与关系变化，在手机端继续使用同一人物时保持连续。

### 7.3 后续扩展

- 用户直接与虚拟伙伴聊天。
- AI 按书名、课程名自行寻找资料，或使用用户提供的链接、内容自主学习。
- AI 主动向用户发起语音通话。

## 八、后续待细化事项

- 人格、情绪、关系和记忆的具体维护与联动机制，交由后续 Agent 设计与算法设计展开。
- 长期目标的推进、成功与失败怎样在具体生活场景中体现。
- 初始设定、候选人物表面介绍的字段，以及可选择的相识方式。
- 聊天教导如何体现知识和技能积累，年龄增长如何影响外貌等人物表现。
- 架空或幻想背景与现实日期、居住地时区的对应细节。
- 声音模拟、语音情绪理解和图像一致性的具体呈现效果。
- “关心”、已读和正在输入等状态的具体展示规则。
- 生活推进窗口的默认值、上下限和修改后的生效方式；具体事件仍需合理推进，不强制每窗口换活动。
- 模拟手机、通知和周围人物状态的具体表示，以及察觉、阅读、回应的判定细节。
- 基础电脑操作工具的具体范围及双端执行方式。
- 长期情感性沉默是否也可由时间或模拟事件结束，以及相应表现；暂时忙碌结束后可以重新判断，但不保证自动回复。
- 虚拟伙伴的记忆范围、朋友圈互动与可见范围变化的规则。
- 后台中断空档在角色叙事中的体现，以及跨空档的年龄、作息和约定衔接；不补算生活事件的原则不变。
- 管理员重置与干预的范围、旧数据处理方式和后续影响。
- 心理学资料来源与筛选标准，模型推荐及依据。

上述待细化内容不预设具体公式、阈值、模型或额外功能。架构、技术选型、工具改造和开发顺序由相应设计文档另行处理。
